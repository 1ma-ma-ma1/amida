## 最初に行う作業
使用するGoogleアカウントは **管理用Googleアカウント** です。

1. Apps Scriptで **サロン抽選管理_2026** を開きます。既存のNFCプロジェクトではありません。
2. このブランチの `gas/Code.gs` を開き、内容をすべてコピーします。Apps Scriptの既存の「コード.gs」を全選択し、置き換えて保存します。既存コードへの追記ではありません。
3. 関数欄で **testWebAppPreparation** を選び、「実行」を押します。Googleの権限確認が出たら、アカウントとアクセス内容を確認して許可してください。
4. 実行ログの **「接続成功」「画面準備成功」** を確認します。この関数は抽選履歴に行を追加しません。
5. エラーの場合はそこで止め、エラー全文をチャットへ送ってください。

公開GitHub版の `SHEET_ID` は `YOUR_SPREADSHEET_ID` です。管理者が台帳IDを設定してから使用してください。チャットで配布する設定済みコードを使用する場合は変更不要です。`DRAW_SHEET_ID` のスクリプトプロパティや `setupDrawSheet` の実行は不要です。
以前の `testDrawWrite` は誤記録防止のため停止しています。`drawAmidaPrize` も引数なしの手動実行では抽選しません。
ユーザーから受け取った変更前のGASと、変更前後のリポジトリは、納品した同じ `salon-amida-backup.zip` に保存します。

## 新しいWebアプリURLを取得
画面準備成功を確認できたら、同じ新GASで次の順に操作します。

1. 右上 **デプロイ → 新しいデプロイ**。
2. 種類の選択の歯車から **ウェブアプリ**。
3. 説明は「サロン抽選管理2026 接続確認」、実行するユーザーは **自分（管理用Googleアカウント）**。
4. アクセスできるユーザーは **全員**。Googleログインを必要としない選択肢です。この選択肢がない場合は表示内容をチャットで知らせてください。
5. **デプロイ** を押し、表示された「ウェブアプリURL」をコピーします。
6. **末尾が /exec のURL** をチャットに送ってください。スクリプトID、デプロイID、/dev URLではありません。

この時点ではURLをお客様に配布せず、NFCの書き換えもしません。スプレッドシートはスタッフ限定の共有のままにします。
新GASのURLはコードに手入力しません。`ScriptApp.getService().getUrl()` で自分自身のURLを使用します。

公式手順: https://developers.google.com/apps-script/guides/web

## 接続方法
利用者は新GASのWebアプリURL（/exec、または /exec?game=amida）を開きます。
GASが `DRAW_UI_REF` に固定したGitHubコミットからHTML・CSS・JavaScriptをサーバー側で読み込み、HTMLサービス内で画面を表示します。
ゲームのデザインとキャラクターの動きはGitHubの既存UIを引き継ぎます。

画面からの抽選はGASの `google.script.run` を使用します。GitHub PagesからGASへの直接fetch、no-cors、JSONP、外部iframeへの呼び出し転送はありません。
この方式は通信経路の問題を避けるための設計であり、実際のGASのiframeや端末の保存領域が動作する保証ではありません。デプロイ後の実機確認が必要です。
直接GitHub Pagesを開いた場合は従来どおり試遊用で、台帳に記録しません。

通信の公式説明: https://developers.google.com/apps-script/guides/html/communication

## 抽選と二重登録防止
1. スタート時に、参加ID・選んだキャラ・経路をIndexedDBの1つのトランザクションで確保します。同じ保存領域の複数タブは同じ参加IDを使用します。
2. 保存できない場合はサーバーへ抽選を送りません。
3. GASがロックを取得し、既存の「抽選履歴」のD列で同じ受付番号を検索します。
4. 保存済みなら当時の特典・日時・番号を返します。E列の「付与済み」などは変更しません。
5. 初回だけGASが5等級から等確率で抽選し、A〜E列に1行追加してから結果を返します。
6. 画面はGASの返した特典・日時・受付番号を表示します。選択キャラの到着地点にその特典を割り当て、歩く・走る・跳ぶ演出を行います。
7. 応答不明時も同じ参加IDを保持します。再試行・再読み込みで新しいIDを発行して送信しません。

列: **抽選日時 / 抽選方法 / 抽選結果 / 受付番号 / 特典の付与**。
既存行や列の削除・置き換えはありません。新しい受付番号は `AM-` と32桁の英数字です。以前の16桁の記録も残します。
1〜5等は各20%。3等・4等がともに温活無料のため、温活無料の合計は40%です。
同じIDの重複登録防止と「1人1回」は別です。別端末・別ブラウザ・データ削除・新しいIDの作成による再参加は本人認証なしでは防げません。
Google側のiframeの保存領域が分離される場合も制限に影響します。端末間の1人1回制限は未実装です。
