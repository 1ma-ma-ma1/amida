# サロンの癒やしのあみだくじ

リラクゼーションサロン向けの、5つの特典を用意できるWeb版あみだくじです。特典内容は未定のため、初期状態は「特典01〜05」のお試し版です。

## 使い方

GitHub Pagesで公開後、そのURLをスマートフォンの通常ブラウザで開いてください。インストールやビルドは不要です。ローカル確認は静的HTTPサーバーをご利用ください。

1. 1〜5のキャラクターから好きな1体を選びます。
2. 「このキャラクターで、くじを引く」を押すと、キャラクターが線をたどって結果を表示します。
3. 結果画面はスクリーンショットで保存できます。「結果の道をみる」を押すと、通った道と5つすべてのゴールの特典名を確認できます。
4. テスト期間中は、結果画面の「もう一度引く」で何度でも試せます。

スマートフォン・タブレット・パソコンに対応しています。キーボードでも操作できます。端末で視差効果・アニメーションの軽減を設定している場合、結果をすぐに表示します。

## サロン名と特典を決めたら

`config.js` の `salonName` と、5つの `benefits` にある `title`（特典名）、`description`（説明・利用条件）を変更してください。項目数は必ず5つにします。説明内の改行は `\n` と記入できます。

すべての内容が確定したら `demo: true` を `demo: false` に変更してください。本番用の案内に切り替わり、同じブラウザで1回だけ抽選できます。特典名・説明そのものは自動変更されないため、5件とも更新してください。

色は `style.css` 冒頭の変数で変更できます。外部フォント・画像サービス・ライブラリへの接続はありません。

## GitHub Pagesで公開する

1. GitHubに公開用のリポジトリ（例：`salon-amida`）を作成します。
2. このフォルダの**中身**をリポジトリのルートにアップロードし、`main` ブランチへコミットします。`index.html` がルートにある状態にしてください。ZIPファイルそのものをアップロードしてもサイトにはなりません。
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment → Source → Deploy from a branch** を選びます。
5. Branchを **main**、フォルダを **/(root)** にして **Save** を押します。
6. デプロイ完了後、Pages設定画面に表示された公開URLを開いてください。

設定を変更するときは、同じ `config.js` を編集・コミットしてください。GitHubの履歴から以前の内容を確認・復元できます。別名のファイルやリポジトリを増やす必要はありません。

GitHub公式手順（2026年11月16日確認）：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 抽選の仕様

- スタートは5本、特典は5種類。1回のくじで1つの結果を表示します。
- 横線を通るたびに隣の縦線へ移動します。5本のスタートはそれぞれ異なる到着地点につながります。
- 特典の配置も毎回ランダムに並べ替えるため、どのスタートを選んでも各特典の確率は1/5です。抽選にはブラウザの暗号学的乱数を使います。
- 各お客様のくじで全5種類が対象です。在庫や「出た特典を除外する」機能はありません。
- テスト版は参加記録を保存せず、何度でも引き直せます。
- 到着地点には、きらめき・宝箱・コイン・クーポン・キャンディのイラストを毎回ランダムに配置します。アイコンの位置と実際の特典の割り当ては別に抽選します。
- 本番では、1キャンペーンにつき同じブラウザで1回です。結果と経路・特典文面・抽選日時をIndexedDBに保存し、再読み込みでも同じ結果を表示します。演出前に保存し、複数タブからの同時抽選はトランザクションで1件にまとめます。保存できない環境では抽選を開始しません。
- 参考コードのCookieと同じくブラウザ単位の簡易制限です。別端末・別ブラウザ・シークレットモード・サイトデータ削除・ブラウザによる保存データ消去まで防ぐ方式ではありません。本人確認やサーバー照合は行いません。
- クーポンの使用済み管理はありません。抽選1回の制限と、特典の利用回数の管理は別です。
- 設定は公開ファイルです。個人情報や秘密の情報は記入しないでください。

## ファイルとバックアップ

`index.html`：画面 / `style.css`：見た目 / `config.js`：店名と特典 / `amida.js`：抽選ロジック / `app.js`：操作 / `storage.js`：参加記録 / `leaf.svg`：アイコン / `.nojekyll`：静的配信用マーカー。

納品時は、同じ内容を `salon-amida-backup.zip` としてフォルダの外に保存しています。このチャットで更新するときは既存ファイルと同じバックアップZIPを上書きし、複製ファイルを増やしません。GitHubへの保存後はコミット履歴もバックアップとして利用できます。

## NFCタグの準備

GitHub Pagesの公開完了後、Pages設定画面に表示される **HTTPSの公開URL** をNFCタグへURLレコードとして書き込んでください。GitHubのリポジトリURLや `.git` URLではありません。スマートフォンでタグを読み取るとブラウザが開きます。サイト内でWeb NFC APIやNFC権限を要求する必要はありません。

通常のプロジェクトURLは `https://1ma-ma-ma1.github.io/amida/` ですが、Pages設定で公開が完了したことを確認してからタグへ登録してください。特典の更新は同じURLに反映されるため、通常はタグの書き換え不要です。実機でNFC読み取りから結果再表示まで確認してから運用してください。

## お試し版から本番へ

`demo: true` では参加記録を保存せず、`demo: false` で本番の参加記録を保存します。本番へ切り替えるとお試しで参加した方も本番に1回参加できます。`campaignId` は同じキャンペーンの間変更しないでください。変更すると全員がもう一度参加できる新キャンペーンになります。URLのクエリ文字列で参加権をリセットする機能は設けていません。

ブラウザ内データはサーバーやGitHubには送信されません。保存済みの特典は抽選時点の文面を保持します。設定を変更しても過去の当選内容は書き換わりません。

## ご褒美ルーレット

あみだくじと同じリポジトリの `/roulette/` に、独立したテスト用ページがあります。「抽選開始」で約3秒ルーレットが回り、5枠の中から1つが当たり、何度でも試せます。A＝くす玉、B＝花吹雪、C＝クラッカー、D＝風船、E＝拍手の画面演出を設定しています。お祝い演出はルーレットの左右にだけ表示します。動きを減らす端末設定では、結果と静止したお祝いイラストをすぐに表示します。

特典が決まったら `roulette/index.html` の `prizes` にある5件の `title` と `description` を更新してください。公開先は [ご褒美ルーレット](https://1ma-ma-ma1.github.io/amida/roulette/) です。

## Googleスプレッドシートへの抽選記録

スタッフがGASの記録用ページから抽選すると、日本時間の抽選日時・当選等賞・管理番号が追記されます。氏名は空欄です。結果画面の管理番号を照合し、スタッフが管理表のD列に氏名を入力します。両ゲームの記録はそれぞれのタブに入ります。テスト中でもGAS版から抽選した分は記録されます。GitHub Pagesの試遊URLからの抽選は記録されません。

1. 管理表に `あみだくじ` と `ルーレット` の2タブを用意します。両方ともA1:D1は `抽選日時`、`当選等賞`、`管理番号`、`氏名` の順にします。管理表は担当スタッフだけに共有します。
2. 管理表で **拡張機能 → Apps Script** を開き、`gas/Code.gs` の中身を既定のコードと入れ替えて保存します。
3. Apps Scriptの **プロジェクトの設定 → スクリプト プロパティ** に `DRAW_SHEET_ID`（管理表URLの `/d/` と `/edit` の間）と `DRAW_STAFF_EMAILS`（利用するGoogleアカウントのメールアドレス。複数の場合はカンマ区切り）を追加します。
4. **デプロイ → 新しいデプロイ → ウェブアプリ** を選びます。実行ユーザーには **ウェブアプリにアクセスしているユーザー** を指定します。アクセスできるユーザーは利用範囲に合わせて **自分のみ** またはGoogleアカウントへのログインが必要な範囲を選びます。記録するスタッフに管理表の編集権限を付けてください。
5. デプロイ後の `/exec` URLを担当者が開き、あみだくじとルーレットで1回ずつ試します。結果画面に「集計表に記録しました。」と出て、台帳の管理番号が一致することを確認します。対象のゲームを直接開くには末尾に `?game=amida` または `?game=roulette` を付けます。

記録に失敗した場合は「記録を再試行」を押します。同じ管理番号の行は追加せず、手入力した氏名も保持します。

[GASウェブアプリの公式手順](https://developers.google.com/apps-script/guides/web)
